# Словарик бэкендера — Perry (Product API)

Краткий словарь аббревиатур и жаргона, которые встречаются в коде, Trello, `DEFENSE_BACKEND.md` и на защите.  
Читать можно сверху вниз или искать по Ctrl+F.

Связанный документ: [DEFENSE_BACKEND.md](./DEFENSE_BACKEND.md).

---

## A–C

| Сокращение | Расшифровка | Простыми словами |
|------------|-------------|------------------|
| **API** | Application Programming Interface | «Дверь» сервиса: набор URL, по которым клиент получает/отправляет данные (у нас REST JSON). |
| **ASP.NET Core** | Active Server Pages .NET Core (истор. имя) | Платформа Microsoft для веб-API и сайтов; на ней стоит `Perry.Api`. |
| **Auth** | Authentication / Authorization (в нашем проекте — сервис) | Отдельный **Auth Service**: логин, регистрация, выдача JWT. Не путать с Product API. |
| **Bearer** | Bearer token (схема HTTP) | Способ передать JWT: заголовок `Authorization: Bearer <токен>`. |
| **BE** | Backend | Серверная часть (Api, БД). Метка на Trello. |
| **CDN** | Content Delivery Network | Сеть раздачи файлов; картинки DummyJSON часто лежат на CDN. |
| **CI / CD** | Continuous Integration / Continuous Delivery | Автосборки и проверки в GitHub Actions (build, test, gitleaks…). |
| **CLI** | Command Line Interface | Работа из терминала (`dotnet`, `npm`), не из GUI. |
| **CORS** | Cross-Origin Resource Sharing | Правила браузера: можно ли сайту с `:3000` звать API на `:5272`. Настраивается в Api. |
| **CRUD** | Create, Read, Update, Delete | Базовые операции: создать / прочитать / обновить / удалить. |
| **CSS** | Cascading Style Sheets | Стили фронта; бэкендеру почти не нужен. |
| **Controller** | (ASP.NET) контроллер | Класс в Api, который принимает HTTP и зовёт Service. |

## D–F

| Сокращение | Расшифровка | Простыми словами |
|------------|-------------|------------------|
| **DB / БД** | Database | База данных; у Product — **PostgreSQL**. |
| **DI** | Dependency Injection | Подсистема .NET: «подставь сервис в конструктор сам» (`AddScoped` и т.д.). |
| **DNS** | Domain Name System | Имена хостов → IP; на защите редко нужно. |
| **DTO** | Data Transfer Object | Объект «для провода»: JSON туда-сюда, не обязательно = таблица БД. |
| **EF / EF Core** | Entity Framework Core | ORM: пишем C#-запросы, EF генерирует SQL к Postgres. |
| **Env / `.env`** | Environment (variables) | Секреты и строки подключения вне git (`ConnectionStrings__…`, `Jwt__…`). |
| **FE** | Frontend | Клиент (React, мобилка). Метка Trello. |
| **FK** | Foreign Key | Внешний ключ в БД («заказ ссылается на productId»). После #94 FK на Users в Product нет. |

## G–J

| Сокращение | Расшифровка | Простыми словами |
|------------|-------------|------------------|
| **GUID / Uuid** | Globally Unique Identifier | Уникальный id вида `a1b2c3d4-…`. У нас `UserId`, `sessionId`, id сущностей. |
| **HTTP / HTTPS** | HyperText Transfer Protocol (Secure) | Протокол запросов. HTTPS = с шифрованием (Auth на Azure). |
| **HS256** | HMAC SHA-256 | Алгоритм **подписи** JWT общим секретом (симметричный ключ у Auth и Product). |
| **HTML** | HyperText Markup Language | Разметка страниц; отдаёт фронт, не Product API. |
| **IaaS / PaaS** | Infrastructure / Platform as a Service | Типы облака; Azure Container Apps у Auth — скорее PaaS. |
| **IDE** | Integrated Development Environment | Cursor / VS / Rider. |
| **IdP** | Identity Provider | Кто выдаёт личность; у нас роль IdP играет Auth Service. |
| **iss / aud** | Issuer / Audience (JWT claims) | Кто выпустил токен и для кого. У нас ≈ `Perry.AuthService` / `Perry.Client`. |
| **JSON** | JavaScript Object Notation | Формат тел запросов/ответов API: `{ "price": 10 }`. |
| **JWT** | JSON Web Token | Подписанный «пропуск» после логина. Product его **проверяет**, не выдаёт (выдаёт Auth). |

## HTTP-статусы, которые стоит знать назубок

| Код | Имя | Когда у нас |
|-----|-----|-------------|
| **200** | OK | Успешный GET/PUT |
| **201** | Created | Часто после POST (создали ресурс) |
| **204** | No Content | Успех без тела |
| **400** | Bad Request | Кривое тело / валидация |
| **401** | Unauthorized | Нет или битый JWT |
| **403** | Forbidden | JWT есть, но роли/прав мало |
| **404** | Not Found | Товара/заказа нет; или не тот URL (login на Product) |
| **409** | Conflict | Например, второй отзыв на тот же товар (#101) |
| **500** | Internal Server Error | Упало на сервере (смотри логи) |

## Путаница: рядом стоящие слова

| Говорят | Не путать с |
|---------|-------------|
| **Authentication** (кто ты) | **Authorization** (что тебе можно) |
| **Auth Service** (выдаёт JWT) | **AuthClaims** (наш код *читает* JWT) |
| **Repository** (git) | **Repository** (класс доступа к БД) |
| **Token** JWT access | **sessionId** корзины (это не логин) |
| **Admin Service** | **admin-эндпоинты внутри Product** (другие вещи) |
| **Migrate** (EF схема) | **merge** (корзина) |
| **Domain** (проект Perry.Domain) | «домен» сайта (perry.com) |

## Мини-шпаргалка на одну карточку

```text
JWT     = пропуск после логина (Auth выдаёт, Product проверяет)
Bearer  = как нести JWT в HTTP
EF      = C# → SQL
DTO     = JSON-форма для API
CORS    = разрешение браузеру звать другой origin
DI      = подстановка зависимостей
PDP     = страница товара
REST    = стиль URL + GET/POST/…
HS256   = чем подписан наш JWT
GUID    = UserId / sessionId
```
