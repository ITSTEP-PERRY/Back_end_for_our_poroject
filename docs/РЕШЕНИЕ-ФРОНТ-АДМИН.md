# Решение по фронту / пушу в команду (26.09)

## Резюме

| Область | Source of truth | Куда пушим |
|--------|-----------------|------------|
| **Наша админка (UI)** | Полный `/admin` (Products / Categories / Reviews / Orders / Users) | **Только у себя** — локально + при необходимости [Teslyar75](https://github.com/Teslyar75/My_Amazon2). **В репо ребят не отправляем.** |
| **Витрина, дизайн, фичи покупателя** | Команда (макеты / архитектура Яны) | **→ ITSTEP-PERRY** (`perry-front` и т.п.), подстраиваемся |
| **Админ-шелл команды** | [perry-admin-front](https://github.com/ITSTEP-PERRY/perry-admin-front) `:3001` | Их репо; мы только подгоняем API |
| **Product API (BE)** | Стыковка Auth, каталог, orders/reviews API | **→ команде** (`Back_end_for_our_poroject`); зеркало у себя [Teslyar75/My_Amazon2](https://github.com/Teslyar75/My_Amazon2) |
| **Auth / Users API** | Влада + perry-admin-service | Azure; не наш код |

**Одной фразой:** в репозитории команды отправляем **всё, кроме нашей админки (UI)**. Админку по возможностям оставляем свою; витрину/дизайн/фичи и бэкенд Product — с ребятами.

## Что именно не пушить в `perry-front` (команда)

- `src/pages/admin/*` — полный функциональный UI (кроме лёгкого редиректа, если команда просит)
- Локальные правки роутера только под нашу `/admin` shell
- Документы вида «своя админка vs их» можно слать, сами страницы админки — нет

## Что пушить в команду

- Витрина, auth, account, API-клиент (Auth / Product / users-api proxy)
- JWT / CORS / миграции / admin **API** в Product (нужны и их `perry-admin-front`)
- Docs по интеграции Auth (#94/#95), без секретов

## Локальный запуск

1. Product API `:5272`
2. Витрина + **наша** админка: `:3000` / `:3000/admin`
3. Эталон команды: `perry-admin-front` `:3001`

Users: **perry-admin-service** (`/users-api`), не Auth `/api/admin/users`.
