## 3. Что сделано по #94 (Product API без Users)

### Зачем
Команда: Product API не должен хранить пользователей. Источник личности — Auth Service; в заказах/корзине/wishlist остаётся только `UserId` из JWT.

Коммит: `d8107c5` — запушен в:
- https://github.com/Teslyar75/My_Amazon2
- https://github.com/ITSTEP-PERRY/Back_end_for_our_poroject

**Удалено**
- Сущности `User`, `UserAccess`, `UserRole` + EF configurations + seed admin user
- `UserService` / `IUserService`
- `AuthController`, `UsersController`, локальный `JwtTokenService` (выдача токенов Product’ом)

**Оставлено / изменено**
- `Order.UserId`, `WishlistItem.UserId` — `Guid` **без FK** на Users
- Миграция `DropUserTables` — drop FK Orders/Wishlist → Users, drop таблиц Users/UserAccesses/UserRoles
- `OrderService` — без `Include(User)` и без `_db.Users`; `RecipientName` из JWT claims при checkout
- Reviews / StockNotify — автор/email из claims, не из БД Users
- Helper `Perry.Api/Auth/AuthClaims.cs` — `sub` / `nameid` / `userId`, `name`, `email`
- JWT validation конфиг: `Jwt:Key|Issuer|Audience|RoleClaimType` + `AuthService:BaseUrl` (значения Auth — после #95)
- `Perry.Web` (Razor account/admin users) — stubs: «auth переехал на Auth Service»

## 4. Что ещё не закрыто по Auth

1. Product API всё ещё валидирует JWT локальным HS256 (`Issuer=Perry`) — **реальные** Issuer/Audience/Key Auth Влада неизвестны (#95).
2. FE нормализует ответы Auth «на глаз» (`accessToken` / `token` / `user`) — после swagger/образца ответа поправить маппинг.
3. Register у Auth — multi-step (`register` → verify-email → complete-registration); наш UI пока шлёт упрощённый `register`.
4. Имена в admin-orders для чужих UserId — через Internal API Auth (`/internal/users/{id}`), credentials TBD.
5. Мерж feature → `main` делает другой человек (как договаривались).

## 5. Фронтенд: почему команде «тяжело копать» (реплика про Яну)

### Суть претензии
> «Выложили код в React-фронт, но без архитектуры, которую заложили с Яной — копать тяжело.»

Это **справедливое** замечание про структуру репозитория, не про то, что витрина «не работает».

### Что заложено с Яной (эталон архитектуры)

Лучше всего видно в **[perry-admin-front](https://github.com/ITSTEP-PERRY/perry-admin-front)**:

```
src/
  Components/     # UI-кирпичи (Buttons, Inputs, Auth, Navigation…)
  forms/          # формы (auth, Category, Product)
  widgets/        # составные блоки
  pages/          # экраны
  app/ + api/     # Redux store / RTK slices
  features/       # middleware и фичи
  shared/, theme/, types/, utils/
```

Стек: **Ant Design + Redux Toolkit + типизированные DeepStyles**.  
Ветка-заготовка той же линии на витрине: `perry-front` → ветка **`alex`** (`Provider` + `store` + antd `ConfigProvider`, пока почти только SignIn).

### Что лежит у нас как рабочая витрина

Ветка **`feature/figma-storefront-port`** (и частично `main`):

```
src/
  app/router.tsx + AuthContext / CartContext / WishlistContext
  pages/*.tsx + pages/admin + pages/account + pages/auth
  styles/*.css          # порт с Razor site.css / auth.css / admin.css
  api/client.ts         # fetch без RTK
  widgets/, Components/ # смесь: часть от линии Яны, часть от порта
```

Стек: **React Router + Context + CSS**, без Redux как единого источника.  
Плюс: каталог/PDP/Account/Admin/скриншоты/API уже связаны.  
Минус: **не следует** папкам/паттернам admin-front → коллегам из линии Яны неочевидно, куда класть код.

### Две линии в одном `perry-front`

Уже описано в [СВЕСТИ-ДВЕ-ЛИНИИ.md](./СВЕСТИ-ДВЕ-ЛИНИИ.md). Кратко:

| Линия | Вход | Стек | Статус |
|-------|------|------|--------|
| **A. Figma-порт** (наш) | `App.tsx` → `router.tsx` | Context + CSS | реально крутится на `:3000` |
| **B. Архитектура Яны** | antd + Redux (`alex`, папки `HomePage/`, `Components/`, …) | Ant + RTK | рядом в репо / другие ветки, роутер порта на неё не смотрит |
| **C. perry-admin-front** | отдельный репо | Ant + RTK | эталон структуры admin |

На `main` после merge часто оказываются **обе** линии A+B → «копаться тяжело».

### Рекомендации к обсуждению (не решение за команду)

1. **Явно выбрать source of truth** для витрины до защиты:
   - либо довести **линию A** и вычистить мёртвый код линии B из `main`;
   - либо перенести рабочие экраны A **внутрь** архитектуры B/Яны (дольше);
   - admin оставить в `perry-admin-front` (C), витринный `/admin` в perry-front — временный или deprecate.
2. Зафиксировать в README: «витрина = ветка X / паттерн Y».
3. Не мержить в `main` полу-архитектуры без plana — только согласованный PR.
