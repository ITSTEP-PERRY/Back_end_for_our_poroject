## 2. Факт по Auth `develop` (проверено)

Из `JwtService` + `appsettings.json` на `develop`:

| Параметр | Значение у Auth | У нас (Product) |
|----------|-----------------|-----------------|
| Issuer | `Perry.AuthService` | ✅ то же (`.env.example` / Development) |
| Audience (client) | `Perry.Client` | ✅ то же |
| Audience (internal) | `Perry.Internal` | ожидаем в Internal client |
| Access claims | `sub`, `email`, **`role`**, `token_use=access`, `jti` | ✅ `Jwt__RoleClaimType=role` |
| Claim `name` | **нет** в access JWT | имя брать из `/me` или Internal, не из токена |
| `AllowedOrigins` (prod) | `[]` (deny, пока не заполнят) | для Azure Auth — спросить Влада |

**Вывод:** код Product под `#96`/`#98` **уже совместим**. Брать нужно не «патч репо», а **подтверждение + credential + CORS origins**.

## 3. Можно взять безопасно

1. **Зафиксировать контракт `#96`/`#98` в Trello/чате** — iss/aud/claims как выше (без смены нашего кода).  
2. **`#97` plaintext `ServiceCredential`** — только в локальный `.env` (не в git); проверить `GET /api/dev/auth-internal-status`.  
3. **Карта эндпоинтов Auth** из их docs (login/register/refresh/internal) — для smoke `#108`.  
4. **Идеи тестов `#85`** из `AuthService.Tests` (WebApplicationFactory, 401/role) — как образец, не копировать проект целиком.  
5. **Идеи колонок/фильтров Users** из `perry-admin-front` — точечно для `#A15`, не переписывать `/admin`.

## 4. Делать у себя (у ребят готового нет / хуже)

| Задача | Почему сами |
|--------|-------------|
| Helpful → `POST /api/reviews/grade/{id}` | API уже у нас; FE ещё local state |
| `[Authorize]` на Product PUT/DELETE | Наша дыра; org Back_end не образец |
| `#M09` EAS | Их mobile — не Expo |
| Variants / video | У ребят нет готового |
| Тянуть **старые** ветки org Back_end поверх My_Amazon2 | Может откатить новое; направление синка: **My_Amazon2 → Back_end** |

---

## 5. Не трогать (сломает демо)

- Считать org Back_end «более новым», чем My_Amazon2 (наоборот: пушим **из** My_Amazon2 **в** Back_end)  
- Bare RN mobile вместо Expo  
- Секреты Auth (`CredentialHash`, Internal signing) в FE/git  
- Переписывание админки под Ant/Redux perry-admin-front без решения команды  
- Ожидание claim `name` в access JWT  
- `SkipSignatureValidation=true` / iss-aud fallback `"Perry"` из старых примеров org Back_end  

---

## 6. Рекомендуемый порядок

1. Написать Владу: iss/aud уже совпадают; claims = `sub`+`email`+`role`; нужен plaintext `#97` + Azure `AllowedOrigins` для `#106`.  
2. Вписать credential → `auth-internal-status` = ok.  
3. Smoke `#108`: Register → Login → Buy.  
4. У себя: Helpful + Authorize PUT/DELETE.  
5. Потом: тесты `#85`, EAS `#M09`; A14/A15 — если останется время.
