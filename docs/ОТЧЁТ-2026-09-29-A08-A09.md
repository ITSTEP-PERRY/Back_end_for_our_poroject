## [#A08] SQL Server → PostgreSQL

### Зачем
Бесплатный/постоянный хостинг Postgres удобнее SQL Server / LocalDB для диплома и Docker.

### Что сделано
| Изменение | Детали |
|-----------|--------|
| Пакет | `Npgsql.EntityFrameworkCore.PostgreSQL` 8.0.11 вместо `EF.SqlServer` |
| DI | `UseNpgsql` в `DependencyInjection.cs` |
| Миграции | SQL Server history → `Persistence/_archive_SqlServerMigrations/` (не компилируется) |
| Новая миграция | `Persistence/Migrations/*_InitialPostgreSQL` |
| DbSeeder | `EnsureReviewGradeReportedColumn` на PostgreSQL `DO $$ … $$` |
| Docker | сервис `postgres:16-alpine` вместо `mssql` |
| Config | `appsettings.Development.json` + `.env.example` → Npgsql connection string |

### Connection string (dev)

```text
Host=localhost;Port=5432;Database=perry;Username=perry;Password=changeme
```

### Запуск

```bash
cd My_Amazon2
cp .env.example .env   # POSTGRES_PASSWORD, JWT_KEY
docker compose up -d postgres
dotnet run --project src/Perry.Api --launch-profile http
# MigrateAsync + Seed при старте
```

Без Docker: локальный PostgreSQL с тем же connection string.

### Важно
- Старая LocalDB `Perry` **не** мигрируется автоматически — это fresh schema + seed.
- Архив SQL Server migrations — только справка, не применять к Postgres.

## [#A09] `GET /api/orders/admin` — фильтры и поля

### Query-параметры (новые + старые)

| Параметр | Назначение |
|----------|------------|
| `page`, `pageSize` | пагинация (default 1 / 20, max 100) |
| `productId` | заказы, где есть позиция с этим ProductId |
| `userId` | заказы пользователя |
| `paymentType` | Cash / Card / Online |
| `q` / `search` | shipping address, recipient name, product name/description, **SKU** |
| `sortBy` | `orderDate` (default) \| `totalAmount` |
| `sortDesc` | default `true` |
| `status`, `fromUtc`, `toUtc`, `orderId` | как раньше |

### Ответ
- `page`, `pageSize`, `totalPages`, `totalOrders`, `totalAmount`, `statusCounts`, compare…
- **items** — те же поля, что у `Mine` (`recipientName`, `shippingAddress`, `paymentType`, полный `items` с `lineTotal` / `imageUrl` / `productDescription`), плюс `userEmail` / `categoryName` при наличии Auth Internal.

Поиск по **email**: без таблицы Users матчится через `RecipientName` и SKU/имя; `userEmail` в ответе — если настроен Auth Internal (#97).
