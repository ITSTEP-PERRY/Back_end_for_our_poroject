## 1. [#96] Auth — Issuer / Audience

### Что должно быть в access JWT (целевой контракт Product)

Product уже настроен на:

```text
iss = Perry.AuthService
aud = Perry.Client
```

Файлы Product (уже есть, менять только если у Auth **другие** строки):

- `My_Amazon2/src/Perry.Api/appsettings.Development.json` → секция `Jwt`
- локальный `.env` рядом с `Perry.Api` (gitignored):

```env
Jwt__Issuer=Perry.AuthService
Jwt__Audience=Perry.Client
Jwt__SigningSecret=<тот же HS256 secret, что у Auth — уже передан в #95>
Jwt__SkipSignatureValidation=false
Jwt__MapInboundClaims=false
Jwt__RoleClaimType=role
Jwt__NameClaimType=sub
```

### Что сделать в Auth (Backend-client)

При **выпуске access token** задайте те же значения, что в конфиге Auth / совпадают с Product.

Пример (.NET `JwtSecurityToken`):

```csharp
var token = new JwtSecurityToken(
    issuer: "Perry.AuthService",      // Jwt:Issuer
    audience: "Perry.Client",         // Jwt:Audience
    claims: claims,
    notBefore: DateTime.UtcNow,
    expires: DateTime.UtcNow.AddMinutes(accessMinutes),
    signingCredentials: new SigningCredentials(
        new SymmetricSecurityKey(Encoding.UTF8.GetBytes(signingSecret)),
        SecurityAlgorithms.HmacSha256)
);
```

В `appsettings` / env Auth:

```env
Jwt__Issuer=Perry.AuthService
Jwt__Audience=Perry.Client
Jwt__SigningSecret=<shared secret — тот же, что у Product>
```

### Как проверить (5 минут)

1. `POST /api/auth/login` → accessToken  
2. jwt.io → Payload → выписать:

```text
iss = …
aud = …
```

3. Написать в [#96](https://trello.com/c/dnk4VUUk) или Telegram.  
4. Если **не** `Perry.AuthService` / `Perry.Client` — Product правит `.env` под ваши строки (#107).

## 2. [#98] Auth — claims в access JWT

### Что читает Product сейчас

Файл: `My_Amazon2/src/Perry.Api/Auth/AuthClaims.cs`

| Смысл | Claims, которые уже пробуем |
|-------|-----------------------------|
| UserId | `nameid` → `sub` → `userId` → `uid` (Guid) |
| Name | `name` → `ClaimTypes.Name` → `unique_name` |
| Email | `email` / `ClaimTypes.Email` / `preferred_username` |
| Role | claim **`role`** (`User` / `Admin`) — через `RoleClaimType=role` |

### Рекомендуемый набор claims при login (Auth)

Вставьте при создании access token:

```csharp
var claims = new List<Claim>
{
    // UserId — канон для Product: sub = Guid строкой
    new Claim(JwtRegisteredClaimNames.Sub, user.Id.ToString()),
    new Claim(JwtRegisteredClaimNames.Jti, Guid.NewGuid().ToString()),

    // Роль — короткое имя "role" (у Product MapInboundClaims=false)
    new Claim("role", user.Role.ToString()), // "User" или "Admin"

    // Желательно для отзывов / RecipientName без Internal API
    new Claim("email", user.Email ?? string.Empty),
    new Claim("name", user.DisplayName ?? user.Email ?? "Customer"),
};
```

**Важно:** не кладите роль только в длинный `http://schemas.microsoft.com/.../role`, если не меняете Product. Сейчас ждём короткое **`role`**.

### Если ваши имена другие

Напишите таблицу в [#98](https://trello.com/c/paCSfdu7). Product подправит `AuthClaims` (#107), например:

```csharp
// пример: если UserId только в "user_id"
user.FindFirstValue("user_id")
```

## 3. [#97] Auth → Product — Internal credential + клиент

### 3.1 Что сделать Auth

1. Завести (или подтвердить) сервис:

```text
Name        = local-service   (или perry-product — тогда скажите имя)
Permissions = users.read, users.manage
Credential  = <случайная длинная строка — PLAINTEXT>
```

2. В Auth храните **hash** plaintext (как у вас `CredentialHash`).  
3. **Plaintext** передайте Product **лично** (не в общий чат, не в git).  
4. Endpoint (уже в [API.md](https://github.com/ITSTEP-PERRY/Backend-client/blob/main/docs/API.md)):

```http
POST /internal/auth/token
Content-Type: application/json

{ "serviceName": "local-service", "credential": "<plaintext>" }
```

Ожидаемый ответ (имена полей уточните, если другие):

```json
{
  "accessToken": "<internal-jwt>",
  "tokenType": "Bearer",
  "expiresIn": 3600
}
```

Затем:

```http
GET /internal/users/{id}
Authorization: Bearer <internal-jwt>
```

### 3.2 Что прописать в Product `.env` (не коммитить)

```env
AuthService__BaseUrl=https://perry-auth-service.orangeplant-910928aa.swedencentral.azurecontainerapps.io
AuthService__ServiceName=local-service
AuthService__ServiceCredential=<plaintext от Влада>
```

В `appsettings.Development.json` уже есть заготовка без секрета:

```json
"AuthService": {
  "BaseUrl": "https://perry-auth-service.orangeplant-910928aa.swedencentral.azurecontainerapps.io",
  "ServiceName": "local-service"
}
```

### 3.3 Код Product — Internal client (вставить при #107)

Создайте файлы ниже в репо **Back_end_for_our_poroject** / `My_Amazon2`.

#### A) Options — `src/Perry.Infrastructure/Options/AuthServiceOptions.cs`

```csharp
namespace Perry.Infrastructure.Options;

public sealed class AuthServiceOptions
{
    public const string SectionName = "AuthService";

    /// <summary>Origin Auth без хвоста / </summary>
    public string BaseUrl { get; set; } = "";

    public string ServiceName { get; set; } = "local-service";

    /// <summary>Plaintext credential — только из env / User Secrets</summary>
    public string ServiceCredential { get; set; } = "";
}
```

#### B) Client — `src/Perry.Infrastructure/Services/AuthInternalClient.cs`

```csharp
using System.Net.Http.Headers;
using System.Net.Http.Json;
using System.Text.Json.Serialization;
using Microsoft.Extensions.Caching.Memory;
using Microsoft.Extensions.Logging;
using Microsoft.Extensions.Options;
using Perry.Infrastructure.Options;

namespace Perry.Infrastructure.Services;

public interface IAuthInternalClient
{
    Task<AuthInternalUserDto?> GetUserAsync(Guid userId, CancellationToken ct = default);
}

public sealed class AuthInternalClient : IAuthInternalClient
{
    private readonly HttpClient _http;
    private readonly AuthServiceOptions _opts;
    private readonly IMemoryCache _cache;
    private readonly ILogger<AuthInternalClient> _log;

    public AuthInternalClient(
        HttpClient http,
        IOptions<AuthServiceOptions> opts,
        IMemoryCache cache,
        ILogger<AuthInternalClient> log)
    {
        _http = http;
        _opts = opts.Value;
        _cache = cache;
        _log = log;
    }

    public async Task<AuthInternalUserDto?> GetUserAsync(Guid userId, CancellationToken ct = default)
    {
        var token = await GetServiceTokenAsync(ct);
        if (token is null) return null;

        using var req = new HttpRequestMessage(HttpMethod.Get, $"internal/users/{userId}");
        req.Headers.Authorization = new AuthenticationHeaderValue("Bearer", token);

        using var res = await _http.SendAsync(req, ct);
        if (!res.IsSuccessStatusCode)
        {
            _log.LogWarning("Auth internal users/{UserId} → {Status}", userId, (int)res.StatusCode);
            return null;
        }

        return await res.Content.ReadFromJsonAsync<AuthInternalUserDto>(cancellationToken: ct);
    }

    private async Task<string?> GetServiceTokenAsync(CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(_opts.ServiceCredential))
        {
            _log.LogWarning("AuthService:ServiceCredential is empty");
            return null;
        }

        const string cacheKey = "auth:internal:token";
        if (_cache.TryGetValue(cacheKey, out string? cached) && !string.IsNullOrEmpty(cached))
            return cached;

        var body = new
        {
            serviceName = _opts.ServiceName,
            credential = _opts.ServiceCredential
        };

        using var res = await _http.PostAsJsonAsync("internal/auth/token", body, ct);
        if (!res.IsSuccessStatusCode)
        {
            _log.LogWarning("Auth internal token → {Status}", (int)res.StatusCode);
            return null;
        }

        var dto = await res.Content.ReadFromJsonAsync<InternalTokenResponse>(cancellationToken: ct);
        var access = dto?.AccessToken;
        if (string.IsNullOrEmpty(access)) return null;

        var ttl = TimeSpan.FromSeconds(Math.Max(60, (dto?.ExpiresIn ?? 3600) - 60));
        _cache.Set(cacheKey, access, ttl);
        return access;
    }

    private sealed class InternalTokenResponse
    {
        [JsonPropertyName("accessToken")]
        public string? AccessToken { get; set; }

        [JsonPropertyName("expiresIn")]
        public int? ExpiresIn { get; set; }
    }
}

public sealed class AuthInternalUserDto
{
    [JsonPropertyName("id")]
    public Guid Id { get; set; }

    [JsonPropertyName("email")]
    public string? Email { get; set; }

    [JsonPropertyName("name")]
    public string? Name { get; set; }

    [JsonPropertyName("role")]
    public string? Role { get; set; }
}
```

> Если JSON Auth использует `access_token` / PascalCase — поправьте `JsonPropertyName` под реальный ответ Swagger.

#### C) Регистрация — в DI Infrastructure (например `DependencyInjection.cs`)

```csharp
services.Configure<AuthServiceOptions>(configuration.GetSection(AuthServiceOptions.SectionName));
services.AddMemoryCache(); // если ещё нет
services.AddHttpClient<IAuthInternalClient, AuthInternalClient>((sp, client) =>
{
    var opts = sp.GetRequiredService<IOptions<AuthServiceOptions>>().Value;
    var baseUrl = (opts.BaseUrl ?? "").TrimEnd('/') + "/";
    client.BaseAddress = new Uri(baseUrl);
    client.Timeout = TimeSpan.FromSeconds(15);
});
```

Нужны using:

```csharp
using Microsoft.Extensions.Options;
using Perry.Infrastructure.Options;
using Perry.Infrastructure.Services;
```

## 4. [#106] Auth — CORS для Front

### Зачем

Браузер на `http://localhost:3000` бьёт в Auth. Без CORS — ошибка в DevTools ещё до Product.

### Что вставить в Auth `Program.cs` (или Startup)

```csharp
builder.Services.AddCors(options =>
{
    options.AddPolicy("Frontend", policy =>
        policy.WithOrigins(
                "http://localhost:3000",
                "http://127.0.0.1:3000",
                "http://localhost:3001",
                "http://127.0.0.1:3001"
                // + prod front origin, когда появится
            )
            .AllowAnyHeader()
            .AllowAnyMethod()
            .AllowCredentials() // если refresh в cookie; если только Bearer в header — можно без credentials
        );
});

// после Build:
app.UseCors("Frontend");
// UseCors — до UseAuthentication / MapControllers
```

Подтвердите в [#106](https://trello.com/c/LIL5NHlr): список origins.

### Обход на время (уже есть на Front)

В `perry-front/vite.config.ts` уже proxy:

```ts
"/auth-api": {
  target: "https://perry-auth-service....azurecontainerapps.io",
  changeOrigin: true,
  secure: true,
  rewrite: (path) => path.replace(/^\/auth-api/, ""),
},
```

В dev Front по умолчанию ходит на `/auth-api` → same-origin → **CORS не мешает**.  
CORS всё равно нужен для prod / прямого `VITE_AUTH_API_URL=https://…`.

Front `.env` (пример, без секретов):

```env
# пусто в DEV = использовать /auth-api proxy
# VITE_AUTH_API_URL=https://perry-auth-service.orangeplant-910928aa.swedencentral.azurecontainerapps.io
```

## 5. [#107] / [#108] — что делаем мы после ответов Auth

### Product (#107)

4. Добавить код §3.3 (Internal client).

```text
GET  /api/health
```

1. `npm run dev` → `:3000`

## 7. Чего НЕ делать

- Не коммитить `Jwt__SigningSecret`, `AuthService__ServiceCredential`, InternalJwt SigningSecret.  
- Не слать полный access JWT в общий Telegram — только `iss`/`aud`/имена claims.  
- Не путать **user** JWT и **internal** JWT.  
- Не ждать `ClaimTypes.Role` длинный URI при `MapInboundClaims=false` — используйте claim **`role`**.
