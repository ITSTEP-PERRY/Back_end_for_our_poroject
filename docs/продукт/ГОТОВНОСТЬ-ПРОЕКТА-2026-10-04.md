## 4. Что уже работает (кратко по контурам)

### 4.1. Product API

- Products (list/facets/popular/by id), Categories (tree + Admin CRUD)
- Cart (JWT/session, merge, checkout без `?userId=`)
- Orders (mine + Admin statuses / filters / statusCounts)
- Reviews (create/list/me, moderation, images, author avatar)
- Wishlist + admin stats; stock notify; `/api/health`
- JWT HS256, CORS `:3000`/`:3001`/`:8081`, Development seed DummyJSON

### 4.2. Desktop (`frontend/`)

- Home, каталог+фильтры, PDP (галерея, buy-box, related, reviews UI + Translate)
- Auth-flow, cart, checkout UA, account (orders/wishlist/settings)
- Legal, admin pages (dashboard/products/categories/orders/reviews/users)

### 4.3. Mobile (`mobile/`)

- Фазы `#M01`–`#M08`: auth SecureStore, shell, home, catalog, PDP, cart/checkout/orders, reviews/wishlist/account
- UI под Figma iPhone; нужен API `:5272`

### 4.4. Infra / docs

- `docker-compose`, GitHub Actions (build + smoke), start-скрипты
- Docs, vibe-prompts, screenshots 04.10

## 5. Риски и пробелы

1. **Auth-контракт** (`#96`–`#108`) — без iss/aud/claims/credential/e2e нет «официального» стыка команд.  
2. **Автотесты** (`#85`) — регрессии cart/checkout ловятся только руками / smoke.  
3. **Helpful** — UI есть, вызов `POST /api/reviews/grade/{id}` нет.  
4. **`#M09`** — нет EAS / smoke на устройстве.  
5. **Variants `#47`** — fashion SKU неполный.  
6. **Безопасность admin product PUT/DELETE** — добить Authorize (`#74` хвост).  
7. **SMTP stub** — письма в лог, не в почту (ок для демо, не для прода).

## 6. Как читать проценты

- **~87–88% продукт** = можно защищать и показывать полный путь покупателя.  
- **100%** в смысле учебного MVP = закрыт список в [ЧТО-ЕЩЁ-СДЕЛАТЬ.md](./ЧТО-ЕЩЁ-СДЕЛАТЬ.md) (P0+P1 минимум).  
- Идеальный прод (реальная почта, жёсткий Auth, полное покрытие тестами, EAS store) — отдельный горизонт после защиты.
