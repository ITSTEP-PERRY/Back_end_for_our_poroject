## A. Стык Auth ↔ Product ↔ Front (P0) — ~+4–5% к итогу

Пакет на доске: **`#105`**. Без него нет «официальной» полной готовности стыка команд.

| # | Задача | Что сделать в нашей версии | Зачем |
|---|--------|----------------------------|-------|
| **#96** | iss/aud access JWT | Получить от Auth и прописать в Product `.env` / config | Один правильный issuer/audience |
| **#97** | plaintext credential local-service | Включить `AuthService__ServiceCredential` + Internal client | Заказы/письма/sync без хардкода |
| **#98** | таблица claims | Сверить `sub`, `role`, email в FE/Product | Admin-guard, «мои» заказы, sellerId |
| **#106** | Auth CORS | Origins `:3000` / `:8081` на Auth | Login с витрины/mobile web |
| **#107** | Product apply контракт | Подтянуть валидацию JWT под `#96`–`#98` | Убрать «у Auth одно, у Product другое» |
| **#108** | Front e2e smoke | Register → Login → Buy на живом Auth+Product | Доказательство для защиты |
| **#105** | Пакет «что предоставить» | Один чеклист в чат/доки | Меньше хаоса между командами |

**Владелец старта:** Auth → затем Product (этот репо) → Front.
