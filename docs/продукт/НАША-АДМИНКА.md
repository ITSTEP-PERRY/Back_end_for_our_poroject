# Наша админка Perry — возможности и скриншоты

**Что это:** функциональная React-админка на `http://localhost:3000/admin`  
(витрина `perry-front`, не путать с командным `perry-admin-front` на `:3001`).

**Статус решения (26.09):** админку UI оставляем **свою**; в репо команды её не пушим.  
См. [РЕШЕНИЕ-ФРОНТ-АДМИН.md](./РЕШЕНИЕ-ФРОНТ-АДМИН.md).

**Скриншоты:** актуальные кадры 04.10 в [`screenshots/2026-10-04/admin/`](../screenshots/2026-10-04/admin/).  
**Карточки Trello:** Epic I — #65 Categories, #66 Products, #68 Users, #69 Reviews, #93 Orders stats.

---

## 1. Обзор

| Раздел | URL | Назначение |
|--------|-----|------------|
| Login | `/admin/login` | Вход учёткой Auth с ролью **Admin** |
| Dashboard | `/admin` | **#A14** KPI месяца, quick actions, recent orders + плитки разделов |
| Customer | `/admin/users/:userId` | **#A15** карточка покупателя + история заказов |
| Products | `/admin/products` | Каталог: список, фильтр, preview, create/edit |
| Categories | `/admin/categories` | Дерево категорий, CRUD, Active/Inactive |
| Reviews | `/admin/reviews` | Модерация отзывов: Hide / Approve / Delete |
| Orders | `/admin/orders` | Заказы, фильтры, stats #93, смена статуса |
| Users | `/admin/users` | Пользователи Auth: роли, soft-delete / restore |

**Паттерн UI:** master–detail — слева список/таблица, справа панель выбранной сущности.

**Доступ:** `AdminShell` пускает только при `roleId === "Admin"` (JWT Auth Service).

## 2. Запуск

```bash
# Product API
dotnet run --project My_Amazon2/src/Perry.Api --launch-profile http
# → http://localhost:5272

# Витрина + наша админка
npm run dev
# → http://localhost:3000/admin
```

Прокси Vite:

| Prefix | Куда |
|--------|------|
| `/api` | Product API `:5272` |
| `/auth-api` | Perry Auth Service (Azure) |
| `/users-api` | perry-admin-service (Azure) — Users |

Нужна учётка Auth с ролью **Admin** (логин через `/admin/login` или общий `/login`).

## 3. Login и оболочка

### 3.1 Login — `/admin/login`

- Форма email/password → Auth `POST /api/auth/login`.
- Сохраняется JWT (`perry_token`); редирект на `/admin/products`.
- Не-Admin → остаётся на login / «Loading…» в shell.

**Локальный DEV-обход (#109):** при `ASPNETCORE_ENVIRONMENT=Development` FE может брать JWT через `POST /api/dev/admin-login` (`Admin` / `Admin`).  
В **Production / Staging** эндпоинт отвечает **404** (контроллер `DevAdminAuthController`) — в проде только реальный Auth.

### 3.2 Shell

- Шапка / drawer: Products, Categories, Reviews, Orders, Users.
- Имя администратора из `/api/auth/me`.
- Logout сбрасывает токен.

### 3.3 Dashboard — `/admin` (#A14)

- KPI: заказы/выручка за месяц, товары в каталоге, отзывы на модерации, Ordered/Shipped.
- Quick actions: Create product · Moderate reviews · Orders · Customers.
- Recent orders (6) → `/admin/orders?selectedId=…`.
- Плитки разделов как раньше.

### 3.4 Customer — `/admin/users/:userId` (#A15)

- Профиль из Users API + заказы Product `GET /api/orders/admin?userId=`.
- Из Users: кнопка **Open customer page**.

## 6. Reviews — модерация отзывов

**URL:** `/admin/reviews` · карточка **#69**

### Возможности

| Действие | Описание |
|----------|----------|
| Фильтры | **All** / **Hidden** (pending) / **Visible** (approved) |
| Search | По product / author / title / body |
| Список | Product, Author, Rating, Status |
| Preview | Текст, теги, дата |
| Hide | `PATCH /api/reviews/disable-many` `{ reviewIds, approved: false }` |
| Approve | `PATCH /api/reviews/disable-many` `{ reviewIds, approved: true }` |
| Delete | `DELETE /api/reviews/{id}` |

Create с витрины (#99–#104): `POST /api/reviews` (JWT), `UserId` только из токена; теги в `PostReviewDto.Tags`. Скрытый отзыв остаётся у автора в `GET /api/reviews/me` (`isApproved=false`).

Требуется JWT с ролью **Admin**.

Фильтры All / Hidden / Visible, таблица модерации.

## 8. Users — пользователи

**URL:** `/admin/users` · карточка **#68**

### Возможности

| Действие | Описание |
|----------|----------|
| Фильтры статуса | **Active** / **Deleted** / **All** |
| Фильтр роли | Admin / User |
| Search | По name / email / login (клиентский) |
| Список | Name, Email, Role, Status (ellipsis на длинных строках) |
| Preview | Дата регистрации, роль, действия |
| Set role | `PATCH …/admin/users/{id}/role` `{ role }` |
| Soft-delete | `PATCH …/status` `{ status: "Deleted" }` |
| Restore | `PATCH …/status` `{ status: "Active" }` |

**Важно:** Users идут на **perry-admin-service** (`/users-api/api/admin/users`), не на Auth и не на Product DB (#94).

## 9. Карта API (сводка)

| Раздел | Backend | Auth |
|--------|---------|------|
| Products / Categories | Product API `:5272` | Create/Update/Delete — желательно Admin; list публичный; `includeInactive` — Admin |
| Reviews admin | Product `/api/reviews` | Admin policy; Hide/Approve via `disable-many`, Delete |
| Orders admin | Product `/api/orders/admin` | Admin |
| Users | perry-admin-service Azure | Admin JWT |
| Login / me | Auth Service Azure | — |

Локально Product валидирует JWT Auth по **HS256 `Jwt:SigningSecret`** из `.env` (#95). `SkipSignatureValidation` только как аварийный DEV-флаг.

## 10. Сравнение с админкой команды

| | **Наша** (`:3000/admin`) | **Команда** (`perry-admin-front` `:3001`) |
|--|--------------------------|------------------------------------------|
| Стек | React Router + CSS (порт Figma) | Ant Design + Redux |
| Функции | Полный master–detail по скринам | Shell / эталон Яны; функции подтянули частично |
| Куда пушим | **Не в ITSTEP** (остаётся у нас) | Их репо |
| Users | perry-admin-service | Тот же сервис (после правки proxy) |

Политика: витрину и BE — с ребятами; **UI нашей админки в их репо не отправляем**.
