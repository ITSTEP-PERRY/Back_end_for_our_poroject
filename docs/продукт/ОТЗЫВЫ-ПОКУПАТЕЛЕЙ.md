# Отзывы покупателей (Customer Reviews)

Документ описывает **как сейчас** устроены отзывы в Perry и **какие задачи** нужны, чтобы сервис работал адекватно: каждый отзыв надёжно привязан к пользователю Auth (`UserId`), виден на PDP и в кабинете автора.

Связано: `#44` create review · `#A04` ReviewController · `#69` admin moderation · Auth `#95`/`#98`.

---

## Модель данных (Product DB)

Таблица **`ProductReviews`** (`Perry.Domain.Entities.ProductReview`):

| Поле | Смысл |
|------|--------|
| `Id` | Guid отзыва |
| `ProductId` | Товар |
| `UserId` | **Guid пользователя из Auth Service** (не локальная таблица Users) |
| `AuthorName` | Имя на витрине (строка; лучше заполнять из JWT `name`) |
| `Rating` | 1–5 |
| `Title` / `Body` | Заголовок и текст |
| `IsApproved` | Модерация: на витрине только `true` (для гостя/покупателя) |
| `CreatedAtUtc` | Время создания |

Связанные таблицы:

- **`ProductReviewImages`** — фото к отзыву (`Url`)
- **`ProductReviewTags`** — теги («easy to use» и т.п.)
- **`ProductReviewGrades`** — helpful / report от других пользователей

На **`Products`**: денормализованные `ReviewCount`, `AverageRating` (сейчас при create через `ReviewRepository` **часто не обновляются**).

## API сейчас (`ReviewController` → `/api/reviews`)

| Метод | Путь | Кто | Назначение |
|-------|------|-----|------------|
| GET | `/api/reviews` | все / admin | Список + фильтры; не-admin видит только `IsApproved=true` |
| GET | `/api/reviews/me` | JWT | Отзывы текущего пользователя (включая скрытые) |
| GET | `/api/reviews/user-product-id/{id}` | все / admin | Отзывы по **userId или productId** (один Guid) |
| GET | `/api/reviews/id/{id}` | все / admin | Один отзыв |
| **POST** | `/api/reviews` | JWT (ожидается) | Создать отзыв |
| PATCH | `/api/reviews/disable/{id}` | Admin | Toggle approve |
| PATCH | `/api/reviews/disable-many` | Admin | Массово approve/hide |
| DELETE | `/api/reviews/{id}` | Admin | Удалить (+ пересчёт count) |
| POST | `/api/reviews/grade/{id}` | JWT | Helpful |
| POST | `/api/reviews/report/{id}` | JWT | Report |

### Create — фактическая логика BE

1. Проверка `rating` ∈ 1…5.  
2. `[Authorize]`; `UserId = AuthClaims.GetUserId(User)` (`sub` / `nameid` / `userId`). Без Guid → 401.  
3. `AuthorName` из JWT display name / email (не с клиента).  
4. Дубликат `(UserId, ProductId)` → **409 Conflict**.  
5. Пишется `ProductReview` с **`IsApproved = true`**; опционально **images** и **tags** (до 8).  
6. Пересчёт `Products.ReviewCount` / `AverageRating` по approved.  
7. Ответ: **201** + тело `CreatedReviewDto` (id, productId, userId, authorName, rating, title, body, createdAtUtc, isApproved, tags, images).

### Front (`perry-front`)

PDP → `reviewsApi.create` → **`POST /api/reviews`** (`productId`, `rating`, `title`, `body`, `tags`, `images`).

Account → `/account/reviews` → **`GET /api/reviews/me`**.

Админка `/admin/reviews` → `/api/reviews` (#A04 / #104).

## Целевой контракт (чтобы «за каждым пользователем закреплялись его отзывы»)

```text
Покупатель (JWT)  →  POST /api/reviews
                      UserId = AuthClaims.GetUserId(User)   // только из токена
                      AuthorName = AuthClaims.GetDisplayName / email
                      ProductId, Rating, Title, Body, Tags?, Images?

БД ProductReviews.UserId  =  Guid из Auth (один человек → много отзывов на разные товары)

GET /api/reviews/me                    → мои отзывы (все статусы свои)
GET /api/reviews?productId=…           → отзывы товара (approved)
Account / PDP                          → показ с привязкой к автору
Admin                                  → moderation по UserId / ProductId
```

Инварианты:

1. **UserId никогда не принимается с клиента** как доверенный источник.  
2. Один пользователь — **не больше одного активного отзыва на один товар** (unique `(UserId, ProductId)`), иначе «закрепление» размывается дублями.  
3. Список «мои отзывы» фильтрует строго по `UserId` из JWT.  
4. После create/delete/moderate пересчитываются `Products.ReviewCount` и `AverageRating`.

## Smoke после закрытия #99–#102

1. Login покупателем A → PDP → Publish review → 201 + отзыв в списке товара.  
2. В БД / `GET /api/reviews/me`: у отзыва `UserId` = Guid A.  
3. Login покупателем B → тот же товар → свой отзыв; список A не содержит отзыв B.  
4. Повторный review A на тот же товар → 400/409 (unique).  
5. Admin Hide → отзыв пропадает с витрины, но остаётся в `me` у A (или пометкой Hidden — зафиксировать в #102).  
6. `Products.ReviewCount` / звёзды совпадают с approved-отзывами.
