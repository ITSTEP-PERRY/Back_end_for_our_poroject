# Свести две линии фронта

На `perry-front` исторически оказалось **две линии** React-кода. Плюс отдельно живёт эталон архитектуры в **perry-admin-front**. Команде из-за этого «тяжело копать» — это ожидаемо, пока не выбран один source of truth.

Связано: [ОТЧЁТ-2026-09-26.md](./ОТЧЁТ-2026-09-26.md) · [ВОПРОСЫ-КОМАНДЕ.md](./ВОПРОСЫ-КОМАНДЕ.md) · орг. [ITSTEP-PERRY](https://github.com/orgs/ITSTEP-PERRY/repositories)

---

## Три «дома»

| # | Где | Стек | Вход | Роль |
|---|-----|------|------|------|
| **A** | `perry-front` · `feature/figma-storefront-port` | React Router + Context + CSS (порт Figma/Razor) | `App.tsx` → `app/router.tsx` | **Рабочая витрина** сейчас (`npm run dev` :3000) |
| **B** | `perry-front` · ветка `alex` + папки на `main` (`Components/`, `pages/HomePage/`, Redux…) | Ant Design + Redux Toolkit | `Provider` + antd | Архитектура **с Яной** (заготовка витрины) |
| **C** | [`perry-admin-front`](https://github.com/ITSTEP-PERRY/perry-admin-front) | Ant + RTK + `Components`/`forms`/`widgets`/`features` | `App.tsx` Routes | Эталон структуры **admin** |

Линия B и репо C — одна школа (папки, DeepStyles, forms, widgets). Линия A — другая (быстрый порт под API и защиту).

---

## Что видно на `main` perry-front

После merge часто лежат **A и B рядом**:

1. **Рабочая (A)** — `src/pages/HomePage.tsx`, `ProductPage.tsx`, `admin/`, `account/`, `auth/`, `styles/*`, `app/router.tsx`.
2. **Линия команды (B)** — `src/pages/HomePage/`, `CategoryPage/`, `Components/`, slices, antd-виджеты Header/Hero… Роутер порта на них **не смотрит** → мёртвый/путающий код.

Отсюда претензия: «выложили код без архитектуры Яны».

---

## Что сделать (решение команды)

### Вариант 1 — защита на линии A (быстрее)
1. Официально: витрина = Figma-порт.
2. Вычистить из `main` мёртвую линию B (папки-дубли, store, если не используются).
3. Admin на защите: либо `/admin` в perry-front, либо показать `perry-admin-front` — **сказать одно**.
4. После защиты — план миграции A → B/C.

### Вариант 2 — витрина на архитектуре Яны (дольше, «правильно»)
1. База = `alex` или каркас как в `perry-admin-front`.
2. Перенести с A: API-клиент (уже с Auth URL), каталог, PDP, Account, скрины.
3. Не мержить полу-порты в `main` без ревью Яны.

### Вариант 3 — два приложения навсегда
- `perry-front` = только покупатель (выбрать A или B).
- `perry-admin-front` = только админка (C).
- Удалить дублирующий `/admin` из витрины.

## Чеклист после решения

1. `npm install` → `npm run dev` → smoke: Home, каталог, PDP, login, account, admin.  
2. API: Product `:5272` + Auth (см. [AUTH-INTEGRATION.md](./AUTH-INTEGRATION.md)).  
3. Одна фраза в README: «архитектура = …».  
4. Закоммитить в согласованную ветку / PR в `main`.  
5. Написать в чат: «оставили A / B / split, удалили …».

Backend (`Back_end_for_our_poroject`) по двум линиям фронта **сводить не нужно** — только фронт и выбор admin-репо.
