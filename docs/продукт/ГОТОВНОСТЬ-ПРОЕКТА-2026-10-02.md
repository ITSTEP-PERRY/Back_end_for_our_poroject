## 3. Что уже работает (по контурам)

### 3.1. Desktop (perry-front)

- Home, каталог с фильтрами, PDP (галерея, buy-box, related, reviews UI)
- Auth-модалки, cart, checkout, My orders / wishlist / account
- Legal, admin: products / categories / orders / reviews / users / login
- Запуск: `Perry Desktop` → http://localhost:3000

### 3.2. Mobile Expo (`mobile/`)

- Фазы `#M01`–`#M08`: env + API-клиент, SecureStore auth, shell/menu, home, catalog, PDP (+ see more / info sheets), cart/checkout/orders, reviews/wishlist/account
- UI сверстан под Figma iPhone (канон в журнале 01.10)
- Запуск: `Perry Mobile` → http://localhost:8081 (нужен API `:5272`)

### 3.3. Product API (My_Amazon2 / Back_end_for_our_poroject)

- Каталог, facets, cart, checkout, orders (в т.ч. `#A11`–`#A13`)
- CORS для Expo Web `:8081` (`#M10`)
- Development seed фото DummyJSON по категориям (02.10)

### 3.4. Auth (Backend-client)

- Сервис живой (Azure + локальный сценарий команды)
- На витрине/мобилке используются login / register / forgot / me
- Документированная «таблица iss/aud/claims + local-service» для Product — ещё в To Do Auth

## 5. Риски и пробелы (кратко)

1. **Auth-контракт** (`#96`–`#108`) — без iss/aud/claims/local-service Product и Front не зафиксируют прод-стык.  
2. **`#M09`** — нет EAS-сборки / финального smoke на устройстве.  
3. **Контент PDP** — нет видео (`#42`), Helpful/Translate без логики (`#45`), variants (`#47`).  
4. **Качество** — мало автотестов критичных сервисов (`#85`).  
5. **Админ UX** — `#A14`/`#A15` у исполнителя; базовые страницы уже есть, нужна целевая доработка по макету.
