## 1. Чем отличаются проекты (снимок на 2026-10-02)

| | Ты (`perry-mobile`) | Мы (`perry-front/mobile`) |
|--|---------------------|---------------------------|
| Стек | RN CLI 0.86, npm | Expo (SDK из `package.json`), bun/npm |
| Натив | Есть `android/`, `ios/` в репо | CNG / без ручного правок натива по умолчанию |
| Навигация | Зависимости `@react-navigation/*` есть; в `App.tsx` пока **ручной `useState` screen switch** | `@react-navigation/native-stack` + `RootNavigator` |
| Экраны сейчас | Legal ×4, CheckOut, Menu, NotFound | Login, Home, Products, Product, Cart, Checkout, Account, Orders, … |
| API-слой | **нет** | `src/api/*` + `AuthContext` + `CartContext` |
| Backend | не подключён | Product `:5272` + Auth Azure |

**Вывод:** UI-заготовки (Menu, Legal, Checkout layout) у тебя уже есть. Дыра MB01 — **API + Login + Home/List/PDP + нормальная навигация**. Наша мобилка как раз закрывает эту дыру кодом, который можно портировать без смены CLI→Expo.

## 2. Что брать у нас, что оставить у себя

### Брать (приоритет)

1. Весь слой **`src/api/`** — `client.ts`, `index.ts`, `types.ts`, `media.ts`, идея `token.ts`  
2. **`AuthContext`** (или упростить до своего store)  
3. Логику данных из экранов: **Home / Products / Product / Login** (не обязательно копировать каждый StyleSheet 1:1)  
4. Список маршрутов и params из `mobile/src/navigation/types.ts`

### Адаптировать

| Наше (Expo) | У тебя (RN CLI) |
|-------------|-----------------|
| `expo-secure-store` | `react-native-keychain` или AsyncStorage |
| `process.env.EXPO_PUBLIC_PRODUCT_URL` | `src/config.ts` / `react-native-config` |
| Metro proxy `/api` (только Expo web) | **не нужен** на native; только абсолютные URL |
| `expo-image` (если есть) | RN `Image` / FastImage |
| Плагины в `app.json` | `AndroidManifest` cleartext, Info.plist ATS исключения для LAN HTTP |

### Не брать

- `app.json` / EAS / Expo Router  
- Админку, web-only proxy из desktop Vite  
- Целиком наши Legal-тексты, если твои экраны Legal уже сверстаны под Figma — только подключи `onPress` к тем же маршрутам  

### Уже сделано у тебя — переиспользовать

- `Menu.tsx` (guest/customer) — повесь реальные `onNavigate('Products' | 'Login' | …)` вместо `setCurrentScreen`  
- Legal / NotFound / CheckOut — оставь вёрстку; checkout позже к Product `orders/checkout`  
- Цвет бренда `#4A7BD9`, иконки SVG — совпадают с каноном Perry

## 5. Навигация: заменить screen-switch на Stack

Сейчас в твоём `App.tsx` что-то вроде:

```tsx
const [currentScreen, setCurrentScreen] = useState("menu");
{currentScreen === "menu" && <MenuScreen ... />}
```

Целевая схема (как у нас, упрощённо):

```tsx
// App.tsx
<NavigationContainer>
  <AuthProvider>
    <Stack.Navigator screenOptions={{ headerShown: false }}>
      <Stack.Screen name="Home" component={HomeScreen} />
      <Stack.Screen name="Products" component={ProductsScreen} />
      <Stack.Screen name="Product" component={ProductScreen} />
      <Stack.Screen name="Login" component={LoginScreen} />
      <Stack.Screen name="Menu" component={MenuScreen} />
      <Stack.Screen name="CheckOut" component={CheckOutScreen} />
      {/* Legal*, NotFound — по желанию */}
    </Stack.Navigator>
  </AuthProvider>
</NavigationContainer>
```

Params (минимум):

```ts
type RootStackParamList = {
  Home: undefined;
  Products: { categoryId?: string; search?: string; sort?: string } | undefined;
  Product: { id: string };
  Login: undefined;
  Menu: undefined;
  CheckOut: undefined;
};
```

Из `MenuScreen`: `navigation.navigate('Products')`, `navigation.navigate('Login')`, и т.д.  
Из карточки товара: `navigation.navigate('Product', { id })`.

Пакеты у тебя уже в `package.json`: `@react-navigation/native`, `@react-navigation/stack`, `gesture-handler`, `safe-area-context`, `screens`. Подключи `gesture-handler` импортом в `index.js` **первой строкой**.

## 6. Порт API-слоя под CLI (чеклист правок)

1. Скопировать `types.ts` без изменений.  
2. `media.ts` — заменить `process.env.EXPO_PUBLIC_PRODUCT_URL` на `PRODUCT_URL` из config; ветку `Platform.OS === "web"` можно упростить (у тебя native-first).  
3. `client.ts` — убрать web-proxy ветки (`return ""` / `/auth-api`); всегда абсолютные `PRODUCT_URL` / `AUTH_URL`.  
4. `token.ts` — заменить SecureStore на:

```ts
import AsyncStorage from "@react-native-async-storage/async-storage";
// getItem / setItem / removeItem
```

или Keychain.  
5. `index.ts` (`authApi`, `productsApi`, …) — почти без правок.  
6. Обёртка Auth — скопировать `AuthContext.tsx`, поправить импорты.

Проверка в отладчике / временной кнопке:

```ts
await productsApi.list({ pageSize: 1 });
await authApi.login("…", "…");
```

## 7. Экраны: что портировать по смыслу

### Login

У нас: форма email/password → `useAuth().login` → navigate Home.  
У тебя: новый `src/screens/auth/Login.tsx` (или `LoginScreen.tsx`). Стили можно сверить с Figma node Log in (`2446:3513`).

### Main (Home)

Данные:

```ts
categoriesApi.tree()

```

UI: hero / категории / горизонтальные ленты — ориентир Figma Main `806:1722` и наш `HomeScreen.tsx`. Не обязательно пиксель-в-пиксель с Expo, но **те же поля карточки**.

`productsApi.list({ categoryId, search, sort, page, pageSize, …filters })`

Figma: `1376:1973`. Related tap → снова `Product` с другим `id`.

### Menu (твой файл)

Оставь вёрстку. Пропы:

- `isAuthenticated={!!user}` из `useAuth()`  
- пункты Catalog / Fashion / … → `navigate('Products', { categoryId })` когда будут id из `categoriesApi`  
- Log in / Log out → Login / `logout()`  
- Legal — твои готовые экраны

## 10. Частые развилки «зачем у них Expo»

| Вопрос | Ответ |
|--------|--------|
| Обязательно ли переходить на Expo? | **Нет.** CLI ок; API одинаковый. |
| Можно ли открыть наш `mobile/` у себя для сравнения UI? | Да: `npx expo start` в их `mobile/` (нужен Node + Product :5272). |
| Что считать source of truth по API? | Product API + Auth; клиентский эталон — `mobile/src/api` **или** desktop `src/api` (один контракт). |
| Конфликт с карточками `#M*` на доске | Серия M* писалась под Expo-помощь; ты закрываешь **MB01** в своём репо — это нормально, бэкенд общий. |
