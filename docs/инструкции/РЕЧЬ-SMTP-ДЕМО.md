# Речь на 1 минуту: stub SMTP и демо-дыры (#88)

## Текст

«Письма в демо идут через **SMTP-stub**: код подтверждения и ссылка сброса пароля **пишются в лог API**, а не уходят на реальный Gmail. Так команда не зависит от App Password и внешнего SMTP на защите.

В коде уже есть переключатель: в `appsettings` поле **`Smtp:UseStub`**. Сейчас `true`. Чтобы включить настоящую почту, ставим `false` и заполняем Host / From / Username / **Gmail App Password** — подключается `SmtpEmailSender`.

На защите мы показываем сценарии Forgot password, VerifyCode и смену email: код виден в консоли сервера или в ответе stub. Это осознанный демо-режим, не отсутствие функции.

Известные упрощения рядом: checkout без отдельной формы адреса (значения по умолчанию). Критичный путь покупателя — регистрация, каталог, корзина, заказ, личный кабинет, React-админка — работает end-to-end. Модалки PDP (Delivery / Payment / Security / Returns / Seller) готовы.

## Шпаргалка на вопросы

| Вопрос | Ответ в одну фразу |
|--------|-------------------|
| Почему нет письма на почту? | Stub: код в логе, чтобы демо не ломалось без SMTP. |
| Как включить Gmail? | `UseStub: false` + App Password в Smtp-секции. |
| Безопасно ли? | Пароль только в user-secrets / env, не в git. |
| Что ещё «заглушка»? | Адрес доставки в заказе — дефолт; реальный SMTP опционален. |
