# Категории товаров (Perry)

Документ для ответа команде на вопросы вида:  
**«У вас есть таблицы категорий — как они будут выглядеть и передаваться?»**

Также: как категории создаются сейчас, что из себя представляет БД, связь с товарами.

Связанный код:
- сущность: `src/Perry.Domain/Entities/Category.cs`
- seed: `src/Perry.Infrastructure/Persistence/DbSeeder.cs`
- админка: `src/Perry.Web/Pages/Admin/Index.cshtml(.cs)` → handler `CreateCategory`
- API: `src/Perry.Api/Controllers/CategoriesController.cs`
- сервис: `src/Perry.Infrastructure/Services/CategoryService.cs`
- БД: LocalDB `(localdb)\mssqllocaldb` → база **`Perry`**

---

## 0. Краткие ответы (для защиты / чата команды)

### У вас есть таблицы категорий?

**Да.** Одна таблица SQL Server: **`Categories`**.  
Отдельных таблиц вроде `CategoryTypes` / `CategoryTranslations` нет.

Иерархия «родитель → дети» хранится **в той же таблице** через поле `ParentCategoryId` (self-FK).

Товар ссылается на категорию полем `Products.CategoryId` → `Categories.Id`.

### Как они выглядят?

1. **В БД** — строка с полями: `Id`, `Name`, `Slug`, `ImageUrl`, `SortOrder`, `IsActive`, `ParentCategoryId`, `CreatedAtUtc`.  
2. **Как дерево (логически)** — например:

```
Electronics
├── Streaming devices
└── PCs & Accessories
Fashion
└── Women's fashion → Casual Women's Clothing → Tops, Tees & Blouses
```

3. **В JSON для клиента** — объект категории + массив `subCategories` (см. §4).

### Как будут передаваться?

| Канал | Как |
|-------|-----|
| **REST API** (для React / внешних клиентов) | `GET /api/categories` → JSON-дерево (корень + прямые дети) |
| **Одна категория** | `GET /api/categories/{slug}` |
| **Внутри товара** | в ответе products: `"category": { "id", "name", "slug" }` |
| **Razor-витрина** | сервер читает БД напрямую (`AppDbContext` / `ICategoryService`), HTML без обязательного REST |
| **Фильтр каталога** | query `categoryId` / `categorySlug` на `/Products` или `?categoryId=` у API products |

Формат обмена по сети для фронта команды — **JSON (camelCase)** поверх HTTP.

## 1. Что из себя представляет наша база данных

- **СУБД:** SQL Server LocalDB.  
- **Имя БД:** `Perry`.  
- **Строка:** `Server=(localdb)\mssqllocaldb;Database=Perry;...` (`appsettings.json`).  
- **ORM:** Entity Framework Core 8, контекст `AppDbContext`.  
- **Миграции** применяются при старте Web/Api (`MigrateAsync`).  
- **Seed** — демо-данные, если таблица `Products` ещё пустая.

### Основные группы таблиц

| Зона | Таблицы (DbSet) |
|------|-----------------|
| Каталог | `Categories`, `Products`, `ProductImages`, `ProductAttributes`, `ProductAboutItems` |
| Отзывы | `ProductReviews`, `ProductReviewImages`, `ProductReviewTags` |
| Корзина | `Carts`, `CartItems` |
| Заказы | `Orders`, `OrderItems` |
| Пользователи | `Users`, `UserAccesses`, `UserRoles` |

Категории — **часть каталога**. Товары без категории создать через админку нельзя (`CategoryId` обязателен).

Подробнее по всей архитектуре: [ПРОДЕЛАННАЯ-РАБОТА.md](./ПРОДЕЛАННАЯ-РАБОТА.md).

## 2. Как выглядит таблица `Categories`

| Поле | Тип | Назначение |
|------|-----|------------|
| `Id` | `Guid` | Первичный ключ |
| `Name` | `string` | Имя на экране («Electronics») |
| `Slug` | `string` | Уникальный URL-код (`electronics`) |
| `ImageUrl` | `string?` | Картинка спота / меню |
| `SortOrder` | `int` | Порядок (меньше — выше) |
| `IsActive` | `bool` | Активна / мягко выключена |
| `ParentCategoryId` | `Guid?` | `null` = корень; иначе родитель |
| `CreatedAtUtc` | `DateTime` | Когда создана |

Связи:
- `ParentCategory` / `SubCategories` — дерево;
- `Products` — товары этой категории;
- удаление родителя с детьми: **Restrict** (сначала дети).

## 3. Демо-данные (что есть «на данный момент» после seed)

Создаются автоматически при первом наполнении:

```
Electronics  (electronics)
├── Streaming devices  (streaming-devices)
└── PCs & Accessories  (pcs-accessories)

Fashion  (fashion)
└── Women's fashion  (womens-fashion)
    └── Casual Women's Clothing  (casual-womens-clothing)
        └── Tops, Tees & Blouses  (tops-tees-blouses)
```

Всего **7** категорий, `IsActive = true`, `ImageUrl` в seed = `null`.

Примеры товаров → категория:
- Roku → Streaming devices  
- футболки → Tops, Tees & Blouses  
- платье → Casual Women's Clothing

## 4. Как категории передаются (контракт для фронта)

### 4.1. Дерево меню / фильтр

`GET /api/categories`

- только **активные** корни (`ParentCategoryId == null`);
- у каждого — **прямые** активные дети в `subCategories`;
- уровни глубже 2-го **в этом ответе не вложены** (их берут по slug или через товары).

Пример:

```json
[
  {
    "id": "...",
    "name": "Electronics",
    "slug": "electronics",
    "imageUrl": null,
    "subCategories": [
      { "id": "...", "name": "Streaming devices", "slug": "streaming-devices", "imageUrl": null },
      { "id": "...", "name": "PCs & Accessories", "slug": "pcs-accessories", "imageUrl": null }
    ]
  },
  {
    "id": "...",
    "name": "Fashion",
    "slug": "fashion",
    "imageUrl": null,
    "subCategories": [
      { "id": "...", "name": "Women's fashion", "slug": "womens-fashion", "imageUrl": null }
    ]
  }
]
```

### 4.2. Одна категория

`GET /api/categories/{slug}` →  
`{ id, name, slug, imageUrl, isActive, parentCategoryId }`

### 4.3. В составе товара

`GET /api/products` / детали товара — вложение:

```json
"category": { "id": "...", "name": "...", "slug": "..." }
```

Фильтр: `GET /api/products?categoryId={guid}`.

### 4.4. Витрина Razor

Не сериализует это дерево в JSON для браузера как SPA: сервер рендерит HTML.  
Данные те же — из БД. Для **perry-front** ориентир — endpoints из §4.1–4.3.

## 5. Как категории создаются на данный момент

Сейчас есть **три** пути.

### 5.1. Автоматически (seed) — при пустой БД

Файл: `DbSeeder.cs`.  
Условие: нет ни одного `Product`.  
Создаются 7 категорий (дерево выше) + демо-товары с `CategoryId`.

Это «начальный набор для диплома / демо», не ручное создание оператором.

### 5.2. Через админку (основной рабочий способ)

URL: `/Admin` (вход: `Admin` / `Admin`).

Форма **«Создать категорию»** (`OnPostCreateCategoryAsync`):

1. Обязательны **Name** и **Slug**.  
2. Slug нормализуется; если такой slug уже есть — ошибка.  
3. Опционально: **Parent** (выпадающий список существующих категорий), **SortOrder**, **Image** (файл → `/uploads/...`).  
4. В БД пишется новая строка:
   - `Id = Guid.NewGuid()`
   - `IsActive = true`
   - `ParentCategoryId` = выбранный родитель или `null` (корень)
5. Сообщение «Категория создана.»

Деактивация / активация — через админку и `ICategoryService` (soft: `IsActive`, без физического DELETE строки в UI-смысле «выключить»).

**Создание товара** в той же админке: обязательно выбрать существующую `CategoryId` + Name; товар без категории не сохраняется.

### 5.3. Через REST API

`POST /api/categories`

```json
{
  "name": "New category",
  "slug": null,
  "parentCategoryId": null,
  "sortOrder": 0
}
```

- `slug` можно не передавать — сгенерируется из `name` + уникализация.  
- Ответ `201`: `{ "id", "slug" }`.  
- `DELETE /api/categories/{id}` — soft-deactivate.

## 7. FAQ (другие типичные вопросы)

**Почему одна таблица, а не «Categories + Subcategories»?**  
Иерархия любой глубины одним self-FK; проще миграции и единый CRUD.

**Почему API отдаёт только 2 уровня?**  
Достаточно для верхнего меню/фильтра; глубокие узлы доступны по `slug` и через товары. При необходимости можно расширить рекурсией в том же endpoint.

**Как фронт должен строить меню?**  
`GET /api/categories` → отрисовать `name` + детей из `subCategories`; переход в каталог по `id` или `slug`.

**Можно ли удалить категорию насовсем?**  
Сейчас акцент на **soft** (`IsActive = false`). Жёсткое удаление ограничено связями (товары, дети).

**Где картинка категории?**  
Поле `ImageUrl`. В seed пусто; через админку можно загрузить файл → путь вида `/uploads/...`.

**Связь с React (perry-front)?**  
Бэкенд отдаёт JSON; фронт не ходит в SQL. Контракт — §4.

## 8. Одной фразой для ответа на ревью

> Категории лежат в одной таблице `Categories` (дерево через `ParentCategoryId`).  
> Выглядят как Name/Slug + опциональные дети.  
> Передаются клиенту JSON’ом: `GET /api/categories` (корень + `subCategories`), плюс вложение `category` в товарах.  
> Создаются seed’ом при первом запуске, через форму в `/Admin` или `POST /api/categories`.
